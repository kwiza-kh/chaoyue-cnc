# 架构与扩展说明

本版参考了 [OpenCADStudio](https://github.com/HakanSeven12/OpenCADStudio) 的公开架构思路（空间宽相位、命令表、文档修订号与分层缓存），**没有复制其 GPL-3 源码**。本项目仍为 MIT 许可。下面的说明针对本仓库自己的实现。

## 1. 模块边界

```
main.rs      Win32 窗口、消息循环、参数解析、自检 / UI 测试 / 基准
app.rs       应用状态、工具与鼠标键盘交互、菜单 / 对话框、图层缓存
model.rs     几何图元、文档 Doc、包围盒、修订号、空间查询入口
spatial.rs   均匀网格索引 SpatialIndex（只负责“哪些图元在附近”）
commands.rs  命令表（名称 / 别名 / 标签 / 动作）
codegen.rs   轮廓串接、补偿、3B / ISO / Mach3 代码
foam.rs      泡沫切割排序、就近进刀、两轴 / 四轴 Mach3
gfx.rs       tiny-skia 绘图、文字 / 图标位图缓存、批处理描边
dxf.rs       DXF 导入
platform.rs  GDI 呈现、文件对话框、刷新率
```

### 新增一个绘图或编辑工具

1. 在 `app.rs` 的 `Tool` 枚举加一个值，并补 `Tool::label`。
2. 在 `canvas_down` 的 `match self.tool` 中处理点位；需要实时预览时在 `draw_preview` 加一个分支。
3. 在 `build_menus`、工具栏或 `commands.rs` 中挂上入口。
4. 修改图元几何后必须让文档缓存失效：
   - 调用 `Doc::add` / `Doc::remove_ids` / `Doc::translate_ids` 时已自动处理；
   - 自己直接改 `doc.entities` 时，改动结束调用 `self.doc.touch_geometry()`。

### 新增一个命令（不新增绘图工具）

在 `commands.rs` 的 `COMMANDS` 表加一行：

```rust
cmd!("mycmd", &["mc", "我的命令"], "显示我的命令", Act::SomeExistingAction),
```

如果行为是全新的，先在 `Act` 枚举加动作，再在 `do_act` 的 `match` 里实现。命令栏、`?` 帮助列表和单元测试会自动包含新行。

## 2. 文档修订号与缓存规则

`Doc` 有两个计数器：

| 计数器 | 何时变化 | 用途 |
| --- | --- | --- |
| `rev` | 任何改动（几何或标题 / 零件名 / 单位 / 备注） | 静态图形层、底图缓存的 O(1) 缓存键 |
| `geom_rev` | 图元位置 / 数量 / 形状变化 | 空间索引、句柄表、包围盒缓存的失效依据 |

公开方法：

- `Doc::revision()`、`Doc::uid()`：一起作为渲染缓存的键。
- `Doc::touch()`：只改元数据（标题栏文字），不重建空间索引。
- `Doc::touch_geometry()`：几何原地修改（旋转、缩放、修剪、脚本改动）后调用。
- `Doc::add` / `remove_ids` / `translate_ids`：内部自动更新修订号与缓存。

**规则：只要绕过 `Doc` 的辅助方法直接写 `doc.entities`，就必须在改完后调用 `touch_geometry()`。** 忘记会导致拾取仍按旧位置、画面不刷新。

## 3. 空间索引

`spatial.rs` 使用均匀网格：

- 网格按文档包围盒和 `TARGET_PER_CELL = 8` 自动分格，单轴最多 512 格。
- 每个图元插入其包围盒覆盖的所有格子；跨越超过 `MAX_ENTRY_CELLS = 128` 格的长图元放入 `big` 溢出集合，每次查询都检查。
- 查询用 `marks` + 世代戳去重，正常鼠标查询不分配结果内存。
- 拖动少量图元时 `SpatialIndex::update` 只移动这些图元；拖动量超过全图 1/4 时退回惰性全量重建。
- `Doc::intersections_in(rect)` 只在光标/视图附近的格子内两两配对，并用“交点属于哪个格子”去重。

### 使用建议

- 拾取用 `Doc::pick(p, tol)`；框选 / 视口裁剪用 `Doc::query_rect(rect, &mut ids)`。
- 不要为了拿一个句柄再线性扫描 `doc.entities`，用 `Doc::get(id)`（内部 O(1) 句柄表）。
- 需要“全部图元”的算法（例如整图统计）可以继续遍历 `doc.entities`，但要避免在鼠标移动路径中做。
- 长图元在 `big` 中，任何查询都会检查，不要依赖“查询格子数量”估算开销。

## 4. 渲染缓存

`app.rs` 维护四层：

1. `background_cache`：渐变 + 网格，按视图、主题、网格开关缓存。
2. `static_cache`：图元轮廓、中心标记、节点、切割路径、标题栏，按 `(doc.uid, doc.rev, 视图, 显示开关, scene_rev)` 缓存。
3. `base_cache`：背景 + 静态层的合成结果，暖帧一次行拷贝。
4. `drag_base`：拖动开始时生成的“挖掉选中图元”的静态层；拖动期间只合成它 + 选中图元覆盖层。

平移时直接按视图位移复制 `base_cache`，结束平移后再精确重建。修改切割路径必须走 `App::set_cut_job`，它会递增 `scene_rev`；否则静态层不会刷新。

空间查询只决定“画哪些图元”，不替代 tiny-skia 的光栅化。整屏显示数万图元时，重绘成本仍主要是 CPU 描边；放大到加工区域后会按视口裁剪，帧率明显提高。

## 5. 测试与基准

```powershell
cd app
cargo test --release                 # 空间索引、命令表
.\target\release\chaoyue-cnc.exe --selftest
.\target\release\chaoyue-cnc.exe --uitest
.\target\release\chaoyue-cnc.exe --bench
.\target\release\chaoyue-cnc.exe --bench-large 20000
```

`--bench-large N` 会生成 N 个图元的压力图，分别测：

- 悬停 + 捕捉：每 300 次鼠标移动；
- 改变视图：30 帧全屏重绘；
- 放大 4 倍后的局部重绘；
- 中键平移（应命中缓存快路径）；
- 拖动选中图元（应命中 `drag_base` 快路径）。

也可以在命令后加 `--screenshot shots\stress.png` 输出压力图，检查是否有漏画。

## 6. 已知边界

- tiny-skia 是单线程 CPU 光栅化；整屏数万图元仍是秒级以下的几十毫秒开销。
- 平移快路径在边缘会露出纯背景色，松开鼠标后立即精确重建。
- 交点显示在网格单元边界上可能重复绘制同一个点（最多 4 次），视觉上无影响。
- `.cnc` 文本格式没有图层、线型、块等 CAD 概念；这些属于后续扩展。
